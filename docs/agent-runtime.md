# 長時間エージェント実行基盤

**ステータス：Draft**

## 目的と権威範囲

READMEの「9. 長時間タスクを走り切る実行基盤」と設計原則「自働化」「プル型生成」を、エンジン非依存の契約として定義します。

## タスク台帳

各エントリは、安定ID、目的、入力リビジョン、依存関係、担当レーン、受入条件、状態、試行回数、リトライ予算、時間・トークン・金額予算、承認状態、停止理由、チェックポイントID、成果物ID、結果ID、次アクションを持ちます。会話履歴だけで未完了作業を管理しません。

## チェックポイント

各ステージは入力ハッシュ、設計グラフリビジョン、ツール・モデル・スキルのバージョン、成果物ハッシュ、検証結果、実行環境、イベント位置を保存します。ブラウザ終了やワーカー再起動後は最後の検証済みチェックポイントから再開し、要件から無意味にやり直しません。

## イベントログ

計画、観測、ツール呼び出し、結果、パッチ、承認、停止、再開、ゲート結果をappend-onlyで記録します。イベントはリビジョンとタスクIDを参照し、リプレイ、監査、回帰評価、知識抽出に使います。

## サブエージェントレーン

部品、回路、レイアウト、シミュレーション、DFM、FWのレーンを分けます。各レーンへの入力は型付きタスク、必要な設計グラフスナップショット、証拠ID、受入条件だけです。出力は型付きハンドオフとして親に返し、検証済み成果物だけをマージします。

## コンテキストと生成

- 会話は要約してよいが、ピン、ネット、制約、DRC、測定など権威ある値はIDで原本参照する。
- 下流ゲートが受入可能になった時点で、次に必要な成果物だけを生成する。未検証候補の在庫を作らない。
- 同じ修正の反復、進捗の振動、成果物の変化なし、ゲート結果の改善なしを無進捗として検知する。
- 時間、トークン、ツール呼び出し、金額、反復回数に上限を置き、ウォッチドッグが超過前に停止する。

## 割り込み

曖昧な要件、未確認の高リスク仮定、ルール免除、予算・納期超過、順序変更が予算を超える場合、または不可逆操作では停止します。不可逆操作の再開には承認IDが必要です。停止時は既知・不確実・選択肢・推奨・再開位置を表示します。

## 型付き冪等ツール

すべてのツールはスキーマ付き入力・出力、相関ID、冪等性キー、タイムアウト、エラー分類、証拠IDを持ちます。操作を`read`、`reversible`、`irreversible`に分類し、発注、公開、削除など不可逆操作は承認IDなしに実行しません。再試行で二重発注や二重パッチが起きないことを契約にします。

## 評価

既知のゴールデンタスクを保存し、モデル、ツール、スキル、プロンプト、ゲートを更新するたびに全工程をリプレイします。電気的妥当性、製造性、コスト、リードタイム、人間介入、停止の正しさ、再開の正しさを採点します。
