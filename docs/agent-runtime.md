# 長時間エージェント実行基盤

**ステータス：Draft**

## 目的と権威範囲

READMEの「9. 長時間タスクを走り切る実行基盤」と設計原則「自働化」「プル型生成」を、エンジン非依存の契約として定義します。

## タスク台帳

各エントリは、安定ID、目的、入力リビジョン、依存関係、担当レーン、受入条件、状態、試行回数、リトライ予算、時間・トークン・金額予算、承認状態、停止理由、チェックポイントID、成果物ID、結果ID、次アクションを持ちます。発注のbudgetは**総発注額**であり、基板fab、部品、実装、送料、税、筐体・機械部品をすべて含みます。通貨はbudgetの`currency`で記録します。予算上限内の発注は、発注前最終ゲートに合格することを条件に、承認IDなしで自動実行します。会話履歴だけで未完了作業を管理しません。

### N7による計画とコンティンジェンシー

タスク台帳の依存関係・所要時間・ワーカー割当からアローダイアグラム（CPM）を生成し、クリティカルパスと遅延伝播を表示します。PDPCは、ツール失敗、在庫消失、fab差戻し、検証不合格、ブラウザ切断などの分岐ごとに停止・再試行・代替・人間通知の計画を生成します。マトリックス図はタスク×担当、変更点×工程、リスク×対策の関係を示します。これらはTaskLedgerとイベントを参照する派生計画であり、不可逆操作の承認や決定論的ゲートを置き換えません。手法の詳細は[`qc-tools.md`](qc-tools.md)を参照します。

## チェックポイント

各ステージは入力ハッシュ、設計グラフリビジョン、ツール・モデル・スキルのバージョン、成果物ハッシュ、検証結果、実行環境、イベント位置を保存します。ブラウザ終了やワーカー再起動後は最後の検証済みチェックポイントから再開し、要件から無意味にやり直しません。

## イベントログ

計画、観測、ツール呼び出し、結果、パッチ、承認、停止、再開、ゲート結果をappend-onlyで記録します。イベントはリビジョンとタスクIDを参照し、リプレイ、監査、回帰評価、知識抽出に使います。

## サブエージェントレーン

部品、回路、レイアウト、シミュレーション、DFM、FWのレーンを分けます。提案（生成）、検証（決定論的ゲートの実行）、統合（マージ判断）を同じ判断で兼ねません。各レーンへの入力は型付きタスク、必要な設計グラフスナップショット、証拠ID、受入条件だけです。レーンは自分の成果物に合格を宣言できず、親は検証結果IDのない成果物をマージしません。出力は型付きハンドオフとして親に返し、入力リビジョン、前提、未解決事項、実行しなかった検証とその理由を含めます。欠落は異常として扱います。

## コンテキストと生成

- 会話は要約してよいが、ピン、ネット、制約、DRC、測定など権威ある値はIDで原本参照する。
- 下流ゲートが受入可能になった時点で、次に必要な成果物だけを生成する。未検証候補の在庫を作らない。
- 同じ修正の反復、進捗の振動、成果物の変化なし、ゲート結果の改善なしを無進捗として検知する。
- 時間、トークン、ツール呼び出し、金額、反復回数に上限を置き、ウォッチドッグが超過前に停止する。

Step Aでは、capとusageを分離した`BudgetUsageSnapshot`をイベントreplayから再構成する。
attemptはledgerの`pending -> running`遷移、tool callは外部process起動として数え、
registry replayはlogical requestの別カウンタとする。tokensとmoneyは計測せず、
usageに明示的な`unknown`を保持する。停止の機械可読な正本はStop Recordであり、

保存する。詳細は[`adr/0034-budget-watchdog-core-contract.md`](adr/0034-budget-watchdog-core-contract.md)を参照する。

## 割り込み

曖昧な要件、未確認の高リスク仮定、ルール免除、予算・納期超過、順序変更が予算を超える場合、または不可逆操作では停止します。ただし、発注前最終ゲートに合格した予算上限内の発注は、不可逆操作であっても承認IDなしで自動実行できる明示的な例外です。予算超過、免除、その他に設定された承認ゲートでは承認IDが必要です。停止時は既知・不確実・選択肢・推奨・再開位置を表示します。エスカレーションは「レーン内のリトライ予算 → 親エージェントへの停止報告 → 利用者への通知」の順とし、各段階に時間と回数の上限を置きます。承認、免除、回答を待って滞留した状態は台帳に可視化し、上限を超えたら無進捗として再通知します。

## 型付き冪等ツール

すべてのツールはスキーマ付き入力・出力、相関ID、冪等性キー、タイムアウト、エラー分類、証拠IDを持ちます。操作を`read`、`reversible`、`irreversible`に分類し、予算上限内かつ発注前最終ゲート合格の発注を除き、発注、公開、削除など不可逆操作は承認IDなしに実行しません。予算超過の発注、免除、その他に設定された承認ゲートは承認IDを要求します。再試行で二重発注や二重パッチが起きないことを契約にします。

## 評価

既知のゴールデンタスクを保存し、モデル、ツール、スキル、プロンプト、ゲートを更新するたびに全工程をリプレイします。電気的妥当性、製造性、コスト、リードタイム、人間介入、停止の正しさ、再開の正しさを採点します。
