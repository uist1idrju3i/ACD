# 検証ゲートカタログ

**ステータス：Draft**

## 目的と権威範囲

READMEの「AIが提案し、決定論的なツールが判断する」と「2 検証ゲートと設計根拠」を実装するための合否契約です。LLMの説明や見た目は合格証拠になりません。

## ゲート

### 整合性ゲート

スキーマ、ID参照、単位、必須属性、リビジョン、パッチの基底、要求と制約の矛盾を検査します。未解決の`unknown`や`assumed`は、影響評価なしにverifiedへ進めません。

### ERC／トポロジーゲート

ネットの接続完全性、ピン方向、電源、未接続、短絡、ドライバ競合、定格を検査します。KiCad ERC、設計グラフの型検査、ピン互換検査の結果を入力とし、警告も重大度と根拠付きで分類します。

### シミュレーション忠実度ラダー

1. トポロジーと単位の軽量検査
2. ブラウザ内の軽量シミュレーション
3. 詳細SPICE、必要に応じてSI／熱解析
4. 実機測定

上位の忠実度を省略する場合は理由と残余リスクを記録します。シミュレーション結果はモデル、入力、ツールバージョン、収束状態、マージンとともに保存し、実測を推論で代用しません。

### DRC／DFMゲート

層、幅、間隔、穴、銅箔、クリアランス、アンテナ、熱、fabプロファイルを検査します。fabからの指摘は構造化して再実行可能なルールへ変換し、修正後にDRCを再実行します。

### 出力検証ゲート

Gerber X2、drill、IPC-2581、BOM、pick-and-place、FWパッケージを生成後に再読込し、設計グラフと照合します。ファイル存在だけでなく、層数、部品数、ネット数、座標、ハッシュ、参照リビジョンを検証します。

### 発注前最終ゲート

全ゲート合格、予算、リードタイム、部品在庫、製造能力、発注内容の一致を再確認します。予算上限内なら既定で自働発注できますが、超過や不確実性があれば停止します。

## 停止・通知

異常時は、(1) **何が**不合格か、(2) **どこで**グラフ・ファイル・ネット・座標・工程のどこにあるか、(3) **なぜ**規則、測定、ツール出力のどれで判断したか、をUIとイベントに記録します。停止地点、再開条件、推奨修正、代替案も表示します。

## 下流へ流さない

検証済みでない設計候補を製造、発注、FW実機試験へ流しません。警告を無視する場合は、ルール免除、理由、影響、承認ID、有効期限を記録し、免除自体を高リスク状態として後続ゲートへ伝播します。

## 高リスク問題を閉じる証拠

発熱、電源品質、信号品質、通信不安定、部品定格、製造ばらつきなど高リスクの問題は、モデルのもっともらしさだけでは閉じません。指定条件での実測、測定器、校正状態、プローブ、時刻、波形または数値、合否基準、設計リビジョンを含む`Evidence`が必要です。
