# ADR-0013: エージェント／ツールの適格性記録

**ステータス：Proposed（未決定）**

## 目的と権威範囲

モデル版、プロンプト版、ツール／container版、タスク種別ごとの適格性と有効期限を
追跡する記録方法の候補を記録する。本ADRは提案であり、実装の前提にしてはならない。

## 文脈

`docs/tool-contract.md`は、既知の合格fixtureと意図的な不合格fixtureでツールを再確認し、
版更新時は旧版の合格結果を新版へ流用しない運用規則を定めている。エージェントのモデル版、
プロンプト版、タスク種別の合格記録と有効期限をどこに置くかは未決定である。

## 決定

エージェントとツールの適格性を、版、タスク種別、確認結果、有効期限、失効条件とともに
記録することを提案する。まだ決定していない。記録形式は既存Evidence、独立記録、または
golden task実行記録からの導出を比較して決める。

## 代替案

- **(a) `Evidence.provenance`の一部として持つ**：現行の出所と版の流れに沿うが、適格性の
  有効期限、失効条件、タスク種別を一つのEvidenceから判定しにくい。
- **(b) 独立した適格性記録を持つ**：失効と再確認を明確にできるが、Schemaとライフサイクル
  の追加設計が必要になる。
- **(c) golden task実行記録から導出する**：実行証跡を再利用できるが、未実行期間による
  期限切れや失敗後の失効を明示的に扱いにくい。

## 判断基準

モデル、プロンプト、tool、container、libraryの版更新時に、依存するEvidenceを遡及無効化
し、再確認が必要か機械的に判定できることを最重要基準とする。合格・意図的不合格fixture、
タスク種別、有効期限、失敗による失効を含むgolden taskの実行記録を再生して評価する。

## 結果とリスク

適格性を版とタスク種別に結び付ければ、古い合格結果の誤流用を防ぎやすい。一方、記録の
粒度が細かすぎると運用負荷が増え、導出だけに依存すると期限管理が弱くなる。候補フェーズ
はPhase 3以降の知識・評価ループでの評価とする提案であり、READMEのフェーズ境界を変更しない。
見直し条件は、版更新、期限切れ、失敗後の無効化と再確認を機械的に判定できない場合とする。
