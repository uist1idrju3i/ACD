# ADR-0028：Phase 5追加によるロードマップ改訂

**ステータス：Accepted**

## 目的と権威範囲

Phase 4完了後の実装計画に、LLMオーケストレーション、自然言語要件対話、
実sourcing／データシートAPIを所有するフェーズが欠落していたため、
README §7のロードマップを改訂する。

## 文脈

現行ロードマップはPhase 4の実行基盤・ブラウザUXから、Phase 5のFW連携と仮想実機、
Phase 6の自働発注へ直接進む構成だった。しかし自働発注の完了条件は、自然言語要件の
構造化、LLMオーケストレーション、実sourcingを前提としている。これらを所有する
フェーズがないままでは、完了条件と実装責任の対応が不明確になる。

## 決定

1. Phase 4の直後に、新Phase 5「AIオーケストレーションと要件対話」を追加する。
2. 新Phase 5はBYOK／セルフホストLLMランタイム、自然言語ヒアリングから
   `Requirement`文書への変換、実sourcing／データシートAPI、サブエージェントレーン、
   コンテキスト圧縮、token／money予算の実計測、MCPツール境界を所有する。
3. 新Phase 5では独自モデルの学習、組織横断ナレッジ共有、大規模基板対応を行わない。
4. 旧Phase 5〜8をPhase 6〜9へ繰り下げる。Phase 0〜4の番号は変更しない。
5. 新Phase 5のゴールデンタスクは、人手のfixture作成なしに自然言語要求から
   Phase 1〜4の全ゲートを通過し、発注前ゲートへ到達することとする。

## 代替案

- 既存Phase 5またはPhase 6へ責務を追加する：実装責任が過密になり、自然言語要件から
  発注までの前提を独立して検証できないため採用しない。
- ロードマップを変更せず、各計画書へ暗黙に追加する：完了条件とフェーズ境界の権威が
  不一致になるため採用しない。

## 結果とリスク

Phase 5が、要件対話から構造化設計入力までの責務を明示的に所有する。後続Phaseの番号、
参照、完了条件は繰り下げ後の番号で記録する。実LLMの接続、実sourcing API、token／money
計測はPhase 4の受入対象外であり、Phase 5で別途検証する。
