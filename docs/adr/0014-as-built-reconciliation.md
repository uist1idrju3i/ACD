# ADR-0014: as-built構成の復元とas-designedとの突合

**ステータス：Proposed（未決定）**

## 目的と権威範囲

製造・組立後の実構成を復元し、as-designedと突合するゲート位置の候補を記録する。
本ADRは提案であり、実装の前提にしてはならない。

## 文脈

実際に組み立てられた基板には、部品ロット、代替部品、手直し、fab側の変更が含まれる
可能性がある。実機Evidenceがどの構成に対する証拠かを特定し、設計リビジョンとの差異を
検出して、依存する結果を遡及無効化する必要がある。

## 決定

as-built復元とas-designed突合を、製造packageから実機完了までの明示的な検証として配置
することを提案する。まだ決定していない。ゲートの位置は三つの候補を、Evidenceの構成
識別性と停止・再開動作で比較して決める。

## 代替案

- **(a) Gate 13（実機完了）の一部にする**：既存の実機Evidenceと近いが、構成差異の検出が
  測定完了に埋もれる可能性がある。
- **(b) 独立したas-builtゲートにする**：差異を下流へ流さない境界が明確になるが、追加の
  gate、runner、Evidence設計が必要になる。
- **(c) 製造package受領時の入口検査にする**：早期に差異を検出できるが、実際の部品ロットや
  手直しを組立後まで確定できない場合がある。

## 判断基準

実機Evidenceが部品、ロット、代替、手直し、fab変更を含む構成に一意に結び付くこと、
差異発見時に依存するEvidenceとVerificationResultを遡及無効化できること、他fixture、
ライブラリ、fabプロファイル、ゲート規則への水平展開を記録できることを確認する。
代表fixtureの受領、組立、差異検出、再検証を再生して決定する。

## 結果とリスク

as-builtを明示すれば、実機結果の適用範囲と設計との差異を監査できる。一方、入口検査を
厳しくしすぎると実機確認まで進められず、Gate 13へ集約しすぎると差異の発見が遅れる。
候補フェーズはPhase 1の実機Evidence契約で評価する提案であり、READMEのフェーズ境界を
変更しない。見直し条件は、構成識別、遡及無効化、水平展開を再現できない場合とする。
