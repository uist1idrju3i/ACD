# ADR-0015: 構造安全チェックの配置

**ステータス：Proposed（未決定）**

## 目的と権威範囲

単一故障点、スニークパス、電源ツリー保護整合、冗長経路の共有を決定論的に検出する
チェックの配置候補を記録する。本ADRは提案であり、実装の前提にしてはならない。

## 文脈

これらの検査はすべての基板へ一律に課すのではなく、設計プロファイルや適用条件に応じて
有効化する可能性がある。プロファイル表現は[ADR-0010](0010-design-profile-and-rule-tables.md)、
ルール評価の状態と有効域は[ADR-0011](0011-three-valued-rule-evaluation-and-validity-domain.md)
の候補に依存する。

## 決定

構造安全チェックを、ERC／トポロジーの拡張、独立ゲート群、またはプロファイルで有効化
する任意チェックのいずれかに配置することを提案する。まだ決定していない。適用プロファイル
外のチェックを合格扱いにせず、未適用理由と追加解析の要否を記録する。

## 代替案

- **(a) 既存ERC／トポロジーゲートを拡張する**：既存の決定論的経路と停止処理を再利用できる
  が、電気的検査と構造安全検査の責務が混ざる。
- **(b) 独立ゲート群にする**：責務とEvidenceを分けやすいが、ゲート数、実行時間、依存関係
  が増える。
- **(c) 設計プロファイルで有効化する任意チェックにする**：適用範囲を調整できるが、
  プロファイルの版管理と未適用時の停止契約が必要になる。

## 判断基準

入力graphとルール表から決定論的に判定できること、誤検出時の停止コストと再開条件を
測定できること、プロファイル別に適用・未適用を再現可能に判定できることを基準とする。
意図的な欠陥fixture、プロファイル差分、unknown影響のケースを用いて、未判定を合格へ
流さず、要詳細解析を停止または広い検証へ送ることを確認する。

## 結果とリスク

配置を明確にすれば、構造上の危険を通常のERC/DRC成功に隠さず扱える。一方、誤検出や
適用範囲の誤設定は停止コストを増やす。候補フェーズはPhase 2（検証と設計根拠）での
評価とする提案であり、READMEのフェーズ境界を変更しない。見直し条件は、決定論的な判定、
profile別の適用、停止からの再開を再現できない場合とする。
