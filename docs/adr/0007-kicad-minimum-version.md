# ADR-0007: KiCad最低対応バージョン

**ステータス：Proposed / 未決定**

## 目的と権威範囲

KiCadの最低対応バージョンを決めるための事実、候補、判断基準、未決定事項を記録します。KiCadの成果物は常に正規設計グラフから生成される投影であり、このADRは設計グラフの権威範囲を変更しません。

## 文脈

KiCad 10.0は2026年3月にリリースされ、KiCad 9.xは現在積極的に保守されていません。KiCadのソースツリーからはSWIG、wxPython、旧Python統合が2026年3月に削除され、IPC APIが将来の自動化境界になっています。公式の`kicad-python`ドキュメントでは、`get_schematic()`はKiCad 11で追加された機能として記載されています。

ACDは、バッチ検証、生成投影、保護されたライブ編集、回路図の入出力に安定した基準を必要とします。基準バージョンの選択は、IPC機能マトリックス、インストール要件、フォールバックとなるファイル生成経路、ゴールデンタスクの再現性に影響します。

## 候補

1. **KiCad 10を基準にする：** `kicad-cli`と基板IPC機能を使い、機能検出と回路図投影向けの生成S式フォールバックを用意する。
2. **KiCad 11を基準にする：** 利用可能な場合は新しい回路図IPCサーフェスを要求し、回路図ファイルの直接生成への依存を減らす。
3. **バージョンマトリックスをサポートする：** KiCad 10と11を明示的な機能プロファイル付きでサポートし、暗黙に機能を縮退させず、未対応操作を拒否する。

## 判断基準

- 必要な基板・回路図IPC操作の利用可能性と安定性
- サポート対象バージョン間での`kicad-cli` ERC／DRC／出力の同等性
- 再オープン検証と決定論的なゴールデンタスク再現性
- ブラウザ、ローカルワーカー、CIモードにおけるインストール・更新負担
- ライブラリ／ファイル形式の互換性と移行動作
- 保護された編集のセキュリティと監査可能性

## 決定

未決定。必要なACD相互運用fixtureとKiCad機能テストが揃った後に、最低対応バージョンとフォールバック方針を選択します。それまでは、[`kicad-interop.md`](../kicad-interop.md)でバージョン対応の機能検出を維持し、すべての対応インストールで回路図IPCが利用できると仮定してはいけません。

## 結果

- 選択した基準にかかわらず、ACDは設計グラフを正規モデルとして維持し、KiCad成果物を投影として扱う必要があります。
- CIは、選択した基準と、明示的にサポートする互換性プロファイルを実行する必要があります。
- 基準バージョンの変更には、このADR、機能マトリックス、ゴールデンタスクfixtureの更新が必要です。
